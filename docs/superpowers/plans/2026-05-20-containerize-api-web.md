# Containerize API + Web (CF Worker → Hono/Bun + nginx) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the API off Cloudflare Workers to a standard Hono/Bun server, and ship the full stack as three production Docker containers — `db` (existing), `api`, and `web` (nginx serving the static Astro build).

**Architecture:** The API keeps its entire Hono app (`apps/api/src/app.ts`) unchanged. A new Bun entrypoint (`server.ts`) starts `Bun.serve` and injects validated `process.env` as Hono's `c.env`, preserving the exact contract the Cloudflare runtime and the existing tests already rely on (`app.fetch(request, env)`). The web image is multi-stage: a Bun build stage runs the existing snapshot + `astro build` (needs `DATABASE_URL` at build time), then an nginx stage serves `dist/` using the already-checked-in `apps/web/nginx.conf`. `docker-compose.yml` gains `api` and `web` services alongside the existing `db`.

**Tech Stack:** Bun 1.3.14, Hono 4, oRPC, Drizzle/Postgres (via `@qafiyah/db`), Astro 6 static, nginx 1.27, Docker Compose.

---

## Key Design Decisions (locked)

- **Env injection, not refactor.** `db.middleware.ts` (`parseBindings(c.env)`) and `logger.middleware.ts` (`c.env.ENVIRONMENT`) are NOT changed. `server.ts` validates `process.env` once at boot and passes it as the second argument to `app.fetch`, which Hono exposes as `c.env`. This mirrors how Cloudflare passes bindings and how `test-utils.ts` / `db.middleware.test.ts` already inject env via `app.fetch(req, bindings)`.
- **Env file rename.** `apps/api/.dev.vars` (a Wrangler-only filename) → `apps/api/.env`, which Bun auto-loads from the package cwd. The root `.gitignore` already ignores `.env`.
- **Web build needs a reachable DB at image-build time.** `generate-snapshot.ts` connects to Postgres over the network. `docker compose build` does NOT join the compose network, so `DATABASE_URL` must point at an independently reachable Postgres (the running `db` container's published `:5433`, or the production DB). Passed as a Docker build arg.
- **nginx config is reused as-is.** `apps/web/nginx.conf` already encodes www→apex, trailing-slash canonicalization, `try_files`, `/_astro/` immutable caching, and UTF-8 charset. The web image copies it to `/etc/nginx/conf.d/default.conf` and `dist/` to `/var/www/qafiyah` (the `root` it already declares).

```ts
// apps/api/src/server.ts
import app from './app'
import { type Bindings, parseBindings } from './env'

const DEFAULT_PORT = 8787

/**
 * Builds the Bun.serve `fetch` handler. Injects validated env as Hono's
 * `c.env` — the same contract Cloudflare's runtime and the API tests use
 * (`app.fetch(request, env)`), so app + middleware code stays unchanged.
 */
export function createFetchHandler(env: Bindings) {
  return (request: Request): Response | Promise<Response> => app.fetch(request, env)
}

function boot(): { port: number; fetch: ReturnType<typeof createFetchHandler> } {
  const result = parseBindings(process.env)
  if (result.isErr()) {
    // biome-ignore lint/suspicious/noConsole: fatal boot diagnostics before the server exists.
    console.error(JSON.stringify({ source: 'server', stage: 'boot', error: result.error }))
    process.exit(1)
  }
  return {
    port: Number(process.env['PORT'] ?? DEFAULT_PORT),
    fetch: createFetchHandler(result.value),
  }
}

// Bun starts a server from the default export only when this is the entry
// module. Importing it in tests (import.meta.main === false) is side-effect free.
export default import.meta.main ? boot() : null
```

## Task 7: Web Dockerfile (multi-stage build → nginx)

**Files:**

- Create: `apps/web/Dockerfile`

The build stage runs the existing snapshot + `astro build` (needs `DATABASE_URL` reachable at build time). The serve stage is nginx with the checked-in `apps/web/nginx.conf`.

- [ ] **Step 1: Create `apps/web/Dockerfile`**

```dockerfile
# syntax=docker/dockerfile:1
# Build context = repo root.

# --- Build stage: snapshot DB → JSON, then astro build ---
FROM oven/bun:1.3.14-alpine AS build
WORKDIR /app
COPY . .
RUN bun install --frozen-lockfile

# generate-snapshot.ts reads the DB over the network at build time.
# Pass a reachable Postgres URL: e.g. the running db container's published
# host port, or the production DB. docker compose build does NOT join the
# compose network, so this must be independently reachable.
ARG DATABASE_URL
ENV DATABASE_URL=${DATABASE_URL}
RUN cd apps/web && bun run build

# --- Serve stage: nginx serving the static dist ---
FROM nginx:1.27-alpine AS serve
# Reuse the checked-in config (www→apex, trailing-slash, /_astro/ immutable, UTF-8).
COPY apps/web/nginx.conf /etc/nginx/conf.d/default.conf
# nginx.conf declares `root /var/www/qafiyah;`
COPY --from=build /app/apps/web/dist /var/www/qafiyah
EXPOSE 80
```
